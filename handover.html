AI Orchestra Web

The long-form documentation site for AI Orchestra — a local-first AI workspace OS. Several AI CLIs and APIs run side by side across projects, delegate work through one orchestrator, are routed by role/cost/quota, and QA always goes through the real test runner. Canvas workspace (the main view)

CLI boxes

One box per agent (Claude, Codex, Composer, Grok, shell, Mistral-headless). Start launches the real CLI as a PTY inside the connected project folder and embeds the terminal in the box — type there instead of a separate PowerShell. Boxes drag and resize; sizes/positions persist.

+ Project folder opens the native folder dialog (Electron) and auto-detects the test command. Hover for QA / change folder / remove; double-click to filter the task panel to that project.

Connectors

Drag a CLI's ● port onto a diamond, pick a role (Reasoning, Coding, Testing, Review, Shell or custom). The role label sits on the arrow; click it to change or remove. A CLI's first connection decides which folder its terminal starts in.

Persistence: GET/POST /api/layout → SQLite kv table. Classic view (sidebar + terminal grid) remains under the header toggle / View menu.

2b. Canvas — right-click, assign, chat

Right-click anywhere

Empty canvas: + Add CLI here, + Add project folder here, place an existing project, Re-detect installed CLIs. On a CLI box: Assign task, Start/Stop session, connect to a project, remove. On a diamond: Run QA, Run Orchestra, show tasks, open folder, remove.

Assign task…

Modal on a CLI: pick the project, pick Solo / Orchestra / Ask, write the request. Solo forces that agent for a headless run. Orchestra forces that agent on the non-QA stages; QA stays Mistral-first. Ask is one question, no edits. Results land in the TASKS panel with the routing explanation.

Chat inside the box

A live session is a real xterm plus an input bar at the bottom of the box. Type a line and press Enter (or Send) — it is written to that PTY. You never need a separate terminal window for ordinary CLI chat.

Keyboard: Ctrl+O add project · Ctrl+N add CLI · F5 re-detect CLIs · Ctrl+Shift+S stop all.

2c. CLI detection — install and uninstall stay in sync

App.refreshHealth() runs at startup and every 60 seconds (POST /api/health/refresh or Help / F5). Each configured provider is probed on PATH (Windows .cmd / .ps1 shims included). Result:

  • CLI found → agent available=true, box shows installed · <version>, Start is enabled.
  • CLI missing → agent available=false, box is dashed red with missing on this computer, Start is disabled, the router skips that agent. Re-install and the next refresh brings it back.
  • API providers (Mistral) stay listed even without a key so the UI can explain the failure.

So a machine that only has Claude + a shell shows only those as startable. Uninstall Codex on that machine and the Codex box corrects itself — no manual registry edit.

4. Architecture

Three packages with a strict dependency direction: core (pure TypeScript, no I/O, deterministic, fully unit-testable) ← runtime (Node side effects) ← providers (adapters). apps/server wires them; apps/web only talks to the daemon.

packages/core

types · events/bus · tasks (state machine, service) · routing/router · quota/quotaManager · permissions/engine · agents (adapter interface, registry) · orchestration (executor, qa, orchestra, askAgent, council, classifyFailure, limits) · config/defaults · testing (SimulatedAdapter, harness)

packages/runtime

process/exec · detect/cli (where/which, .ps1/.cmd shims) · terminal/sessionManager (node-pty → pipe fallback) · git/gitService · testing/testRunner · context/contextBuilder · fs/editApplier · persistence/db (node:sqlite) · secrets · config/loadConfig (YAML)

packages/providers

base/headlessCli (generic) · claude · codex · cursor (Composer & Grok) · mistral (HTTP, proposed-edit protocol) · shell · createAdapters() factory (unknown CLIs → generic adapter; simulate → SimulatedAdapter)

Why these choices

  • Core is pure. Every decision (route, escalate, quota state, permission verdict, council stop) is a function of inputs plus an injected clock/ID generator → tests never touch a CLI or network.
  • Two channels per provider. Interactive PTY for the human; headless print mode (claude -p, codex exec, agent -p, Mistral HTTP) for orchestration. No agent ever scrapes another agent's terminal.
  • Safety outside the LLM. Permission engine, quota reserve and budget guard run in core on every attempt regardless of what any model says.
  • Electron desktop + loopback daemon instead of Tauri (no cargo on this machine). Dev uses system Node + tsx; packaged mode runs build/daemon/daemon.mjs with ELECTRON_RUN_AS_NODE=1. node-pty 1.1.0 is N-API so installers set npmRebuild: false.

6. Routing — explainable by construction

TaskRouter.route(input) evaluates every candidate agent in two passes and returns a RoutingDecision with per-candidate scores, reasons, and rejection causes. The UI prints the summary verbatim.

Reserve justifications (the only keys that make Grok eligible automatically)

primary_unavailableprimary_quota_constraineduser_requestedreasoning_hardsecond_opinionprimary_disagreement

Even with a justification, Grok is rejected for generate_tests, fix_tests, qa, lint, format, analyze_logs, shell unless the user forces it. A forced agent still cannot bypass an exhausted pool.

7. Quota pools & the Cursor reserve

Pools

poolagentssource
claudearchitectlocal estimate (budget 200)
openaicoderlocal estimate (budget 200)
mistraltestertoken-based estimate (budget 1000)
cursoradvanced_worker + reasoning_backuplocal estimate (budget 100) · reserve 0.40

Cursor pool model

Composer calls debit the same pool Grok needs. When remaining ≤ 40 % the pool state becomes reserved: Composer loses automatic eligibility (QA falls back to Codex), Grok keeps it.

used by Composer ─────────▶ ◀── 40 % protected for Grok

State ladder: unknown → healthy → moderate → low → reserved → exhausted. Sources: provider-reported fraction > user budget + usage counters > qualitative state set by user or inferred from a quota_failure. Unknown is never faked as a number.

8. QA workflow & escalation (core/orchestration/qa.ts)

1 · contextgit diff + changed files + nearby tests (+ failing output on retry) — ~1 KB in the demo, never the repo
2 · Mistral attempt 1proposed edits applied only under permission scope (tests/**)
3 · real runnerproject.commands.test; exit code decides
4 · Mistral attempt 2receives the actual failing output
5 · classifyclassifyFailure() → code_or_test · infrastructure · reasoning · unknown
6 · escalate oncecode/infra → Composer (or Codex if cursor reserved) · reasoning → Claude · never Grok
7 · runner againpass → completed · fail → failed, human review
Hard failures (quota, auth, crash, timeout) skip the retry and escalate immediately; a quota_failure marks the pool exhausted, an authentication_failure marks the agent unavailable. Budget guard stops the chain at max_agent_calls / max_cursor_usage / runtime.

9. Execution modes

Solo

One task, one agent (auto-routed or forced). App.solo() → POST /api/solo.

Orchestra

Workflow stages (plan → implementation → qa → final_review). Each stage is a child task routed normally; QA stages delegate to the QA workflow; stage summaries (not raw logs) flow forward. runOrchestra().

Council

Bounded rounds; every participant is a routed task (reserve rules apply, Grok as participant = second_opinion). Stops on [CONSENSUS] from all, max rounds/messages/calls, timeout or user stop. Ends with a structured JSON summary (decision, reasoning, disagreements, risks, implementation, testing). runCouncil().

Ask Agent

One focused question, no file edits, answer returned over the bus. Asking a reserve agent requires a justification. askAgent().

10. Permissions, concurrency, limits

Permission engine

read / search / diff / run tests / lint / create test / modify scoped source / shellallow
modify unscoped source · install dependency · delete · git commit · git pushask
force push · deploy production · drop database · destructive shelldeny

Rules layer workspace → project → agent → mode; most specific wins; a base-level deny is never relaxed. classifyShellCommand() maps raw commands (rm -rf, git push -f, DROP TABLE, terraform apply, npm install x…) to actions deterministically. ask → permission.requested event → UI Approve/Deny (default deny after 10 min).

Limits & kill switches

BudgetGuard per workflow: max_agent_calls 12, max_retries 2, max_council_rounds 4, max_cursor_usage 6, max_reasoning_agents 2, max_runtime 30 min. STOP ALL AGENTS aborts every run, cancels open tasks, kills agent terminals. Per-task stop in the task list.

Edits: API agents return proposedEdits; the applier refuses path traversal and consults the permission engine per path. CLI agents edit directly; changed files are read back from git status, never from the model's claims.

Concurrency (pending, Phase 6): per-file task locks and worktrees. Today the UI shows one project at a time per workflow; runs can overlap but there is no lock yet.

11. Context builder (runtime/context/contextBuilder.ts)

Builds a ContextBundle = git diff (relative to the project dir, nested repos supported) + changed source files (≤12, ≤12 KB each) + nearby tests (same dir, __tests__, tests/, name-related, ≤6) + failing output + previous summary; binary/noise paths (.sqlite, lockfiles, images) are filtered; total budget 120 KB with graceful trimming. renderContext() turns it into prompt text for single-prompt CLIs.

12. Task model & events

Task state machine

queued → running → testing → completed
   │        │   ↑        │
   │        │   │        └→ failed → queued (retry / escalation)
   │        ↓   │
   │     waiting / blocked / review
   └→ cancelled (any non-terminal state)

Illegal transitions throw. Task records: attempts (agent, outcome, failure, testResult), escalations, routing decisions, usage per pool, changed files, notes.

Event families (typed, in core/types/events.ts)

workspace.* project.* agent.{started,stopped,message,failure} task.{created,assigned,started,status,completed,failed,escalated,cancelled,updated} test.{started,completed,failed} file.changed git.diff.updated git.conflict quota.{updated,low,reserved,exhausted} council.{started,round,completed} permission.{requested,approved,denied} routing.decided terminal.{started,data,exit} orchestra.log kill.all

Every event is persisted to SQLite (except terminal.data) and broadcast on the WebSocket; the UI is a pure consumer.

16. Configuration (orchestra.config.yaml)

Keys follow the brief: providers, agents, quota_pools, projects, workflows, qa_policy, permissions, limits, secrets. Everything merges over defaultWorkspaceConfig(). Secrets: env var first, else a configured command (1Password, pass, …); nothing is written to disk. Env flags: ORCHESTRA_SIMULATE=1, ORCHESTRA_PORT, ORCHESTRA_CONFIG, ORCHESTRA_AUTO_QA=1 (auto-QA 20 s after the working tree settles while an agent terminal is open), ORCHESTRA_HOST (default loopback).

18. How to extend

Add a custom CLI

providers:
  my_ai:
    type: cli
    command: my-ai
    args: ["--interactive"]
    capabilities: [implementation]
    quota_pool: my_pool
    headless:
      args: ["--print"]
      prompt_via: arg
agents:
  helper:
    provider: my_ai
    role: [implementation]
quota_pools:
  my_pool: { agents: [helper] }

No code needed: createAdapter() gives unknown CLIs the generic HeadlessCliAdapter. Override parseOutput() in a subclass for custom JSON.

Add a workflow

workflows:
  bugfix:
    mode: orchestra
    lead: architect
    stages:
      - { name: diagnose, agent: architect, kind: plan }
      - { name: fix, agent: coder, kind: fix_bug }
      - { name: qa, agent: tester, kind: generate_tests }

Stage kinds drive routing weights; agent: auto lets the router choose.

Change policy

qa_policy picks the primary tester and escalation targets; limits cap calls/rounds/cursor usage; permissions can be scoped per agent/project/mode. Router weights live in ROLE_WEIGHTS / W in router.ts with tests in router.test.ts — change both together.

20. Decisions & trade-offs

  • npm workspaces, not pnpm — pnpm absent; nothing in the design depends on it.
  • Source exports (exports: ./src/index.ts) — tsx/vitest/Vite consume TS directly; no build step for packages. Add tsc emit before publishing anything.
  • node:sqlite — zero native build; WAL mode; JSON columns for nested structures.
  • node-pty with pipe fallback — install scripts needed npm approve-scripts (npm 11 gate); the launcher does this on first run. Windows kill goes through taskkill /T to avoid node-pty's console-list helper.
  • Mistral proposed-edit protocol — API models cannot touch disk; the orchestrator applies edits through the permission engine, which also gives a clean audit trail.
  • Git as the change oracle — changed files come from git status before/after each CLI run; nested project directories handled with --show-prefix / --relative.
  • Core packages consolidated — the brief's dozen packages are directories inside core; split later if they diverge.
